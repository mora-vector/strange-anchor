# Decisions retained at the junction

These are engineering decisions from the supplied conversation, not new Sanskrit
scholarship or a claim that a fictional crew persona holds cryptographic keys.

| Original proposition | Revision | Consequence |
| --- | --- | --- |
| Two matching narratives independently re-derived the grammar | Both read the same character plate; the six-karaka question carried that structure forward | Record transmission and adaptation, not independent discovery |
| Definitions already enforce the policy | A name and comment grant or deny nothing | Compile contracts into service settings and test inside the affected service |
| A `.drv` proves recovery | Recipes, input availability, and actual recovery are different facts | Retain selected closures; record restoration separately |
| A custom merge retains all claims | Priorities discard definitions before the custom merge | Preserve source records outside the merged configuration |
| Flat attribute sets guarantee equal authority | Topology and authority are separate | Keep the mesh inventory descriptive; do not claim governance enforcement |
| Empty peer lists establish no communication | Network namespaces and socket families have specific scopes | Document those scopes; do not imply Unix-socket or inherited-descriptor isolation |
| A failed curl proves filtering | DNS, HTTP errors, or an unhealthy server can also fail | Use literal addresses, healthy controls, service-context probes, and distinct HTTP-error classification |
| Knowledge gaps require recovery evidence | Knowledge, availability, and recovery are orthogonal | Unknown/withheld entries may honestly carry no recovery evidence |
| Two hashes establish correctness | They establish equality of observed bytes within the declared scope | Keep correctness, reproduction, independent administration, and adoption separate |

The current release is a bounded prototype: one compiler, a single-guest
experiment, and an evidence recorder. It intentionally leaves production hardware,
backups, migration approval, authenticated release promotion, and fleet routing
unspecified. Those require concrete operating choices beyond this experiment.
