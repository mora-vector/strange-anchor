# Lopa export contract 1.0

`sandhi.registry.export` now emits both `/etc/sandhi/lopa.json` and
`/etc/sandhi/lopa-v1.json`. Both are immutable snapshots generated by NixOS.
The first retains its exact gap-ID-keyed shape: status, availability, reason,
blocksActivation, and recoveryEvidence entries containing only kind/reference.
New provenance fields are deliberately projected out of that legacy file.

The versioned envelope contains `schema = "sandhi.lopa"`, `schemaVersion = "1.0"`,
`provenance`, and `gaps`. `schemas/lopa-v1.schema.json` is its standalone JSON Schema
(2020-12). The schema is shipped with the validator; it is not fetched at runtime.

Envelope provenance has `sourceRevision` and `recorder`. Each gap and each recovery
reference has `sourceReference`, `assertedBy`, `recordedAt`, and `sha256`. Every field
is present, with null meaning unknown/not supplied. These are operator declarations:
no clock, Git identity, model identity, or evidence verification is inferred.
The optional digest identifies the referenced bytes, not a signature. `recordedAt`
is a preserved source string, not a parsed or authenticated timestamp.

Knowledge status, availability, and recovery evidence keep their independent
meanings. Even an entry labelled `verified-restoration` is a claim until its source
is inspected. Export never resolves a gap or waives a blocking assertion. Treat
these as public configuration: avoid private paths, identities, and secrets.

## Compatibility and migration

Consumers must select a supported schema/version explicitly. The bundled reader
supports exactly 1.0, rejects unknown fields/versions and duplicate JSON keys,
and does not coerce missing provenance into an inferred identity. Future minor
versions may add optional information but require an updated reader/schema;
1.0 readers fail closed on them. Changes to required fields, enums, or meaning
require a new major version, a separately named export, and a migration document.

The legacy export remains available in this development series. No removal date
or automatic consumer migration is declared. Reading legacy data is insufficient
to reconstruct provenance; migration must use null for absent information and
name the importing recorder separately from the original contributor.

## First workload

`packages.x86_64-linux.lopa-audit` provides `sandhi-lopa-audit SNAPSHOT`.
It hashes exact input bytes, validates the envelope, lists blockers, unattributed
gaps, and evidence references, and emits a JSON report on stdout. Exit 0 means a
valid snapshot with no blockers, 2 means valid with blockers, and other nonzero
exits indicate validation/I/O failure. It does not retrieve any evidence or sign
any result. Every reference is labelled `verification: "not-performed"`.

Import `examples/lopa-audit.nix` to add the manual service
`sandhi-contract-lopa-audit.service`. It reads the required snapshot, has no peer
grants, and writes an atomic completed report under
`/var/lib/sandhi-contract-lopa-audit/report.json`. A failed invocation may leave its
temporary file; an older completed report remains tied to its own input digest.
Budgets are 50% CPU, 128 MiB memory, 30 seconds per attempt, and no extra starts in
300 seconds. It is not automatically scheduled. `tests/workload.nix` exercises
the real package inside the generated unit. Consult VALIDATION.json for measured
status; presence of the test is not evidence that it has run.
