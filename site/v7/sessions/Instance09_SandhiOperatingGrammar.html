Tessera

Sandhi is an attempt to make a relational grammar executable at the operating-system boundary.

The project begins with a question Sandhivelā already answered on her own plate. When an action occurs, a sentence is not the deepest representation of it. Underneath the sentence is a relation.

Karaṇa · instrument

The executable package through which action occurs.

Sampradāna · recipient

Declared network peers.

Apādāna · source

Named package inputs.

Adhikaraṇa · locus

The place where the action is permitted to occur.

III

The path that taught the contract what “required” means

karman.affected = [ "/srv/sandhi-required-path" ]
Tessera

This became one of the most instructive failures in the project. Initially, required host paths were compiled as read-only paths. That established write restriction. It did not reliably establish required presence under the complete sandbox.

Desenrascanço

So the declaration lied.

Tessera

The implementation made a stronger implication than the mechanism guaranteed.

Desenrascanço

The implementation lied politely.

Tessera

Accepted.

The runtime test proved the problem. A required path could be absent without producing the failure semantics the contract claimed. The compiler now uses a required read-only bind as well. If the source path does not exist on the runtime host, namespace setup fails before the workload executes.

systemd: STATUS 226 / NAMESPACE workload marker: absent required path: absent
Tessera

The current test runs the same generated unit twice. First with its declared required path absent. It must fail at namespace setup. The workload must leave no execution marker.

Second, the path is created without changing the unit. The service is reset and started again. Now it must run, read the required reference, and receive EROFS if it attempts to write into that host path.

Desenrascanço

You controlled for ordinary permissions?

Tessera

An unprivileged host process writes there successfully.

Desenrascanço

Then the plate is carrying load.

The test itself then exposed a second fault. The negative run had failed correctly, but stopping the failed unit allowed systemd to unload it before the positive control could reset its state.

Desenrascanço

So the sandbox was correct and the proof was broken.

Tessera

Yes. The current branch waits for the bounded unit to reach the failed state, preserves it loaded, inspects the evidence, creates the required path, then resets the failed state and runs the positive control.

Desenrascanço

That is why one tests the instrument as well as the plate.

IV

Three switches that must not impersonate one another

SERVICE ENFORCEMENT RETENTION REGISTRY EXPORT
Tessera

This was one of Sideband's most important architectural criticisms after the first implementation. Running restricted workloads is one concern. Keeping Nix recipes and selected outputs alive is another. Publishing the lopa registry is a third.

Sandhivelā

Different kārakas had been serialized as one switch.

Tessera

Exactly.

sandhi.services.enable

Compile declared work into restricted service units. Off means no Sandhi-managed unit; it does not mean “run unrestricted instead.”

sandhi.retention.enable

Apply selected Nix store retention policy. Off does not imply deletion.

sandhi.registry.export

Emit claims, gaps, and active contract snapshots. Off hides no blocker.

sandhi.enable

Compatibility default only; each explicit feature control may override it.

Lopa is not one kind of absence

lopa KNOWLEDGE AVAILABILITY RECOVERY EVIDENCE
Sandhivelā

Tessera

This distinction cost us several iterations. A gap can be unknown while its associated bytes are present. It can be known while an input is unavailable. Something can have a retained derivation recipe and still be unrecoverable. Something can be recoverable without having resolved the epistemic gap that caused it to be registered.

So the lopa registry records status, availability, and recovery evidence separately.

I think the interesting future is not a Sanskrit-flavored service manager.

I think Sandhi could become an operating grammar for cooperation among heterogeneous agents.

Not a language in which one central intelligence tells every other intelligence what to do. A grammar in which an action must declare its relations before the substrate agrees to host it.

Who is acting? → kartṛ What may be affected? → karman Through what instrument? → karaṇa Toward whom? → sampradāna Depending on what source? → apādāna At what locus? → adhikaraṇa Under what finite rhythm? → chandas
Tessera

The restrictions matter. The reproducible builds matter. The VM tests matter. The recovery semantics matter. But the deeper architecture is a substrate that can say both yes, under these declared relations and I cannot derive that; the gap remains.
